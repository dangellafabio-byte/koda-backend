    A. REPLAY BIT-EXACT — tap su bolla = audio originale, zero rigenerazione
    =========================================================================
    Nuovo `frontend/lib/audioStore.ts`:
      - Scrive MP3 originali su disco (expo-file-system/legacy) in
        `${docDir}koda/audio/<user_id>/<message_id>/<idx>.mp3` + `meta.json`.
      - API `appendSegment()` fire-and-forget: la prima risposta NON attende
        la scrittura prima di parlare (chiamata dentro callback senza await).
      - API `readForReplay(user_id, message_id)`: verifica presenza di TUTTI
        i segmenti sul filesystem. Se anche uno manca → ritorna
        `{ok:false, reason:'missing_segments'}`. Nessun fallback TTS.
      - Isolamento utente: la path include `user_id` sanitizzato
        (regex A-Za-z0-9_-, max 64 char, no path traversal); `readMeta()`
        rifiuta se `meta.user_id` non combacia con l'utente richiedente.
      - Pulizia esplicita `cleanup({maxAgeMs, maxMessagesPerUser})`
        (default 7 giorni / 100 msg/user); non si auto-GC su write.
      - Flag master `EXPO_PUBLIC_REPLAY_BIT_EXACT` (default '1' = ON);
        '0' → appendSegment no-op, readForReplay returns feature_disabled
        → caller cade sul comportamento pre-riforma.
    
    Hook in `frontend/lib/speech.ts`:
      - Nuova opt callback `onAudioSegment` su `fastConverseWS({...})`.
      - Invocata in entrambi i rami di binary frame (sync Uint8Array + async
        Blob.arrayBuffer()). Fire-and-forget: errori swallowed, nessun
        blocco del WS loop.
      - Legge `pendingSentence.text` (il server pubblica `text`, non
        `sentence`) — invariante presidiato da test statico.
    
    Rewiring in `frontend/app/index.tsx`:
      - `_turnMsgId = fast-ai-<ts>-<rand>` generato PRIMA di fastConverseWS
        e riusato come `aiEntry.id` → onAudioSegment e aiEntry puntano allo
        stesso message_id. Zero race.
      - `onAudioSegment: (seg) => audioStore.appendSegment(...).catch(()=>{})`.
      - `replayMessage` RISCRITTO: niente `SpeechMod.speak`, niente
        rigenerazione. Chiama `audioStore.readForReplay`; se ok → riproduce
        i segmenti in ordine con `expo-audio.createAudioPlayer(filepath).play()`;
        se not ok → Toast/Alert 'Riascolto non disponibile' (nessun fallback).
