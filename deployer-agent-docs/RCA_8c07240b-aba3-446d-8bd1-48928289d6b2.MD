```
2026-11-08 00:40:10,156 - server - WARNING - [startup] TTS providers routes NOT registered: unexpected indent (koda_tts_prefs.py, line 18)
```
Reproduced in the eph sandbox against this run's exact source:
```
$ python3 -c "import py_compile; py_compile.compile('backend/koda_tts_prefs.py', doraise=True)"
  File "/app/scratch/backend/koda_tts_prefs.py", line 18
    restituisce comunque ``elevenlabs``.
IndentationError: unexpected indent (koda_tts_prefs.py, line 18)
```
Root cause in the file: the module docstring is broken — an `import os` statement was pasted INTO the middle of the opening `"""..."""` docstring (around line 17), so the remaining docstring prose (`restituisce comunque ...` at line 18) is parsed as indented code. Head of file:
```
...
 * ``get_provider_for_uid(db, uid) -> "elevenlabs" | "inworld"``
   — default "elevenlabs" se nessun doc. Il resolver fa anche doppio
     controllo whitelist (defense in depth): se un utente NON autorizzato
     per qualche ragione avesse un doc con ``inworld``, il resolver
"""
import os                                    <-- inserted inside the docstring
     restituisce comunque ``elevenlabs``.    <-- line 18, now bare indented text -> IndentationError
 * ``consume_switch_token(db, uid, token) -> {provider, consumed}``
...
```
**Consequences:** per-user TTS provider selection (the `koda_tts_provider_prefs` inworld/elevenlabs switch) is not mounted, the Inworld adapter is unavailable, and **TTS telemetry is disabled** ("telemetria disabilitata"). This is global (all devices), but it directly degrades the step5_demo "Lascia Andare" TTS path and is almost certainly why the telemetry collections are empty (see §4). This is a backend source defect; the fix is yours to make, in `backend/koda_tts_prefs.py`.
