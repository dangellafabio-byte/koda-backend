# RCA — Ollenya (app-finder-408) deploy failures

## Verdict
**SOURCE-level failure in the EAS OTA (Metro `expo export`) lane.** Not infra, not K8s, not image push, not secrets, not resource limits. All 5 deploy attempts today (runs from 20:53 → 21:17 UTC) died at the same place. The last healthy run is `235d4391-38b8-4581-abc1-2a5bf7d7f4ca` (12:17 UTC) — that is what remains live.

## Which stage failed
The `build` step runs two lanes in parallel: backend Docker build and the EAS OTA update (`expo export` / Metro bundle → `eas update`). The **EAS lane** crashed during Android bundling. The backend Docker lane was still healthy at the time (it was mid-install of `torch==2.13.0+cpu`); the whole build aborts because the EAS lane returned exit 1. Nothing reached mongo/secrets/deploy/health_check/promote.

## Exact error (from Cloud Build log, run 8b31c420)

```
[expo-cli] Android Bundling failed 50151ms node_modules/expo-router/entry.js (1705 modules)
[expo-cli] SyntaxError: /workspace/frontend/app/index.tsx: Unexpected reserved word 'await'. (2958:10)
  2956 |   noSpeechCountRef.current = 0; // reset per la prossima sessione manuale
  2957 |   try {
> 2958 |     await speakAwareness(pickLine(awarenessLoopExit));
       |     ^
✖ Export failed

```

## Root cause
`frontend/app/index.tsx` uses `await` inside a **synchronous** callback. The enclosing function is a `useEffect(() => { ... })` that begins at **line 2858** — a plain (non-`async`) arrow function. Inside it there are **two** `await` call sites:
- **line 2958**: `await speakAwareness(pickLine(awarenessLoopExit));`
- **line 2970**: `await speakAwareness(pickLine(awarenessLinesNoAudio));`

`await` is only legal inside an `async` function (or a module top level), so this is a hard JS parse error. Metro's `expo export` does a full cold bundle and hits it deterministically. Verified in the sandbox that the pattern `(() => { try { await f(); } catch {} })` throws `SyntaxError: await is only valid in async functions`, matching the build exactly.

### Why preview "looked fine"
- The Metro **dev server** bundles lazily/incrementally and may have been serving a cached bundle from before this edit, so the broken module was never re-transformed in the running preview.
- The pre-deploy verification used `ast.parse` on `backend/server.py` (Python) and a backend `/api/health` check — neither touches `index.tsx`. The TSX file was never syntax-checked. `expo export` in the deploy is the first full cold bundle, so it's the first thing to fail.

## Fix (recommended — preserves control flow)
A `useEffect` callback must stay synchronous (React must not receive a Promise/async cleanup). So do **not** mark the `useEffect` arrow `async`. Instead de-await both calls into fire-and-forget with a `.catch`:

- Line 2958 →
  ```ts
  // early-exit branch: the `return;` at ~2960 fires regardless, so fire-and-forget is safe
  speakAwareness(pickLine(awarenessLoopExit)).catch((e) => {
    console.warn(`[OLLENYA_HF_NOSPEECH_EXIT] speakAwareness error:`, e);
  });
  ```
- Line 2970 →
  ```ts
  speakAwareness(pickLine(awarenessLinesNoAudio)).catch((e) => {
    console.warn(`[OLLENYA_HF_NOSPEECH_PROMPT] speakAwareness error:`, e);
  });
  ```
Remove the now-redundant surrounding `try/catch` for each (the `.catch` replaces it).

**Alternative** if the "speak THEN proceed" sequencing actually matters at the 2970 site: wrap just that logic in an async IIFE — `(async () => { try { await speakAwareness(...); } catch(e){...} })();` — but note the inner `return` no longer short-circuits the `useEffect`, so the de-await form above is the cleaner match for the existing control flow. Both forms were verified to parse in the sandbox.

Then sanity-check the whole file before redeploying, e.g. `cd frontend && npx tsc --noEmit` or a full `npx expo export` locally, so no other `await`-in-sync-callback sites remain.
