MOTIVO DEL FALLIMENTO
---------------------

La build TestFlight iOS v1.0.113+7 (build number EAS 1114) installata
sull'iPhone dell'utente NON ESEGUE il download automatico degli update
OTA, pur avendo:
- runtime 1.0.113 (matcha il runtime degli update pubblicati)
- expo-updates SDK regolarmente incluso

Non sono in grado di determinare la causa esatta dal solo ambiente
pod di sviluppo, perché non ho accesso a:
- L'IPA installato sul dispositivo dell'utente
- La configurazione effettiva embedded nel bundle TestFlight
  (channel, updates.url, policy checkAutomatically)
- Il log runtime di expo-updates sull'iPhone

Cause tecniche ipotizzabili ma non verificabili senza intervento
umano di supporto Expo/Emergent:

1. La build TestFlight compilata dalla pipeline Emergent potrebbe
   avere expo-updates disabilitato o configurato con
   `checkAutomatically: NEVER`.
2. Il channel embedded nel bundle potrebbe essere diverso da quelli
   pubblicati sul CDN (preview / production / development).
3. Il campo `updates.url` embedded potrebbe puntare a un project
   Expo diverso da quello configurato in `app.json` — a causa
   dello step "Normalizing app.json" della pipeline Emergent che
   sovrascrive il file al build time.
4. Il project Expo `d022431b-fda8-48d2-ba1c-bbbe0ef617df` (usato
   internamente dalla pipeline Emergent per la build) è
   inaccessibile al token EXPO dell'utente (fabiod.labor):
   pubblicare update su quel project fallisce silenziosamente
   nel workflow.
